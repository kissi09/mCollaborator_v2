# mCollaborator desktop

A native window around the mCollaborator web app — its own icon, its own taskbar
entry, no address bar — built with [Wails v2](https://wails.io).

Everything here is additive. `../backend` is not modified, not imported, and not
copied: the desktop app **runs the real server binary as a child process** and
proxies the window's requests to it. The server that ships inside the desktop
app is byte-for-byte the server that ships on its own, which means one thing to
test rather than two.

## How it fits together

```
  mCollaborator.exe  (this project, Wails + WebView2)
        │
        │  1. picks a free loopback port
        │  2. starts the server as a hidden child process
        │  3. waits for /health
        │  4. opens a window whose asset handler is a reverse proxy
        ▼
  mCollaborator-server.exe  (../backend, unchanged)
        │
        ▼
  %APPDATA%\mCollaborator\   database, evidence, reports, logs
```

The two executables must sit in the same directory. The installer puts them
there; if you copy them by hand, copy both.

## Building

```powershell
.\build.ps1
```

Three steps: build the server from `../backend`, regenerate the icon, then build
the app and — if NSIS is installed — the installer. Everything lands in `dist/`.

| Flag | Effect |
|---|---|
| `-SkipServer` | Reuse the staged server binary instead of rebuilding it |
| `-NoInstaller` | Build the `.exe` only, even when NSIS is available |

### Prerequisites

| Tool | Needed for | Install |
|---|---|---|
| Go 1.21+ | everything | already present |
| Wails CLI v2 | the app | `go install github.com/wailsapp/wails/v2/cmd/wails@latest` |
| WebView2 runtime | running the app | ships with Windows 10/11; the installer also checks |
| NSIS | the installer only | `winget install NSIS.NSIS` |

No C compiler and no Node/npm are required. Wails needs neither on Windows, and
this project has no frontend build step — the UI is served by the backend.

## The icon

`tools/mkicon` builds `build/windows/icon.ico` from the brand assets already in
the web app. It is regenerated by `build.ps1`, so the icon always tracks the
artwork rather than being a binary someone dropped in once.

Neither source image works alone. `cyberteq-mark.png` is the monogram at a
usable 282px but white on transparent — dropped straight into an `.ico` it is
invisible against Explorer's white background. `apple-touch-icon.png` is the
finished artwork, dark tile and all, but only 180px, smaller than the 256px
entry Windows wants. So mkicon samples the tile colour and the monogram's
proportions from the artwork, redraws the tile at high resolution, composites
the full-resolution monogram onto it, and emits six entries: 256, 128 and 64 as
PNG, 48, 32 and 16 as uncompressed BMP, which is the layout Windows ships its
own icons in.

## Files worth knowing about

| Path | Notes |
|---|---|
| `main.go` | window options, the reverse proxy, single-instance lock |
| `server.go` | finding, starting, health-checking and stopping the server |
| `proc_windows.go` | hides the server's console window |
| `build/windows/installer/project.nsi` | **edited by hand** — see below |
| `frontend/dist/index.html` | placeholder; Wails wants a frontend dir, this app never serves from it |

### project.nsi is customised

Wails generates it once and then leaves it alone. Two changes were made and both
matter:

1. **It installs `mCollaborator-server.exe` as well.** The stock template ships
   only the main executable, which would install cleanly and then refuse to
   open.
2. **Uninstalling does not delete your data.** The stock template removes a
   WebView2 data path under `$AppData`; this one removes only
   `%APPDATA%\mCollaborator\webview` and leaves the database, the evidence and
   the generated reports where they are. An uninstall must not take a pentest's
   findings with it.

If you ever delete `project.nsi`, Wails will regenerate a stock one and quietly
undo both.

## Known gaps

- **The `.exe`'s own version metadata is empty.** Right-click → Properties →
  Details shows blank fields on `mCollaborator.exe`. Wails v2.15 is not applying
  `build/windows/info.json` in this configuration; the icon resource from the
  same step does get applied. The **installer** carries correct metadata, so
  Programs and Features looks right. Fixable with a hand-generated `.syso` if it
  starts to matter.
- **Unsigned.** SmartScreen will warn on first run until the executables are
  signed with a code-signing certificate.
- **PDF export still needs Word or LibreOffice** on the machine. The desktop app
  changes nothing about that: it runs the same server, which looks for the same
  engines. On Windows with Office installed, this is already satisfied.

## macOS and Linux

`main.go` and `server.go` are portable, and `proc_other.go` / `fatal_other.go`
cover the platform-specific pieces, so the shell itself should build for both.
Two things stand between that and a shippable build:

- Wails cannot cross-compile. macOS and Linux builds must run on those
  platforms — unlike the server, which cross-compiles from anywhere.
- PDF export on macOS and Linux is LibreOffice-only; there is no Word path.
